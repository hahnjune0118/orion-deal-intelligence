# Orion 5–7분 시연 안내

시연 주제는 **원문 증빙 → 분석가 검토 → 승인된 상태 변경 → 실사 질문 재정렬 → 결과 내보내기**입니다. 아래는 구현된 합성 자료를 설명하는 진행 순서이며, 실제 기업의 검증 결과나 LLM 성능 평가가 아닙니다.

## 시작 전

`ORION_WEBAPP_USER_GUIDE.md`에 따라 앱을 실행하고 `http://127.0.0.1:8050`에 접속합니다. `Northstar Analytics`를 선택한 뒤 `Reset demo`를 누릅니다. 심화 사례의 식별자는 `nb`이며 Foundation의 별도 Northstar `ns` 사례와 혼합하지 않습니다.

화면 확대는 우선 100%로 두고 문서 다운로드 폴더를 확인합니다. 실제 화면의 현재 순위와 변경 이유를 설명하고, 외운 숫자를 화면과 무관하게 제시하지 않습니다.

## 0:00–0:50 — 무엇을 판단하는 작업대인가

`Deal overview`에서 기업 개요와 상단 `Priority watchlist`를 보여줍니다. 이어 `Investment thesis`로 이동하여 투자 가설과 반대 가설이 함께 표시되는 것을 확인합니다.

설명 예시: “회사가 제시한 고객 수, 성장 전망과 수익성 주장에 대해 어떤 증빙이 부족한지 확인합니다. 이 자료는 모두 합성 사례이며, 문서에 기록되어 있다는 사실과 독립적인 사실 검증을 구별합니다.”

## 0:50–1:40 — 질문에서 원문으로 이동

`Evidence explorer`의 근거 또는 주장 행을 선택합니다. 오른쪽 `Source inspector`에서 발췌문, 문서 버전과 원문 위치를 보여줍니다. `Adaptive DD matrix`로 이동해 첫 질문의 점수와 요청 문서를 확인합니다.

원본 확인이 필요하면 왼쪽 문서 목록에서 해당 문서를 선택하고 `Download original source`로 내려받습니다. 검토·감사 이력의 시각은 합성 이벤트에 맞춘 재생 시각이며 실제 발표 중 클릭한 시각은 아닙니다.

설명 예시: “제품의 우선순위는 증빙 부족·재무 중요도·확보 가능성의 기존 공식으로 계산합니다. 표를 정렬해도 계산 순위는 바뀌지 않습니다. 원문 인용이 있다고 해서 주장 전체가 검증된 것은 아닙니다.”

## 1:40–2:40 — T1 계약 증빙을 검토하고 승인

`Analyst review`로 이동합니다. 오른쪽 이벤트에서 `nb_update_t1`을 확인하고 `Original source`를 펼칩니다. Aster 유상 계약은 있지만 검수·청구·수금 자료가 아직 별개라는 내용을 읽습니다. `Review note`에 검토 이유를 적은 뒤 `Approve update`를 누릅니다.

Top-3와 `Latest committed ranking comparison`을 함께 보여줍니다. Aster 계약 질문은 해결되지만 Birch 계약, 검수, 현금 수령과 독립 고객 여부 등 남은 질문은 해결된 것으로 처리되지 않는 점을 설명합니다.

## 2:40–3:30 — T2 검수와 첫 수금은 전액 수금과 다름

`nb_update_t2`의 원문을 확인하고 승인합니다. Aster 검수와 첫 수금에 대한 요건은 충족되지만, 청구액 USD 120,000 중 수금 USD 90,000에 대해 잔액 USD 30,000이 별도 질문으로 남는 것을 설명합니다.

설명 예시: “계약금액, 청구액, 매출 인식과 현금 수령은 서로 다른 항목입니다. 이번 증빙의 적용 범위를 Aster에서 Birch로 확대하지 않습니다.”

## 3:30–4:20 — T3 새 증빙이 있어도 Top-3가 같을 수 있음

`nb_update_t3`을 열고 고객별 비용 자료를 확인한 뒤 승인합니다. Aster의 연간 반복 기여이익은 USD −24,000, 구현 업무를 포함한 첫해 기여이익은 USD −54,000이라는 합성 원문의 산식을 설명합니다.

비용 항목의 범위는 완성되어도 긍정적인 수익성 주장은 반증됩니다. 이 질문의 기존 증빙 부족 점수가 이미 최대였으므로 **이 이벤트에서는 Top-3가 유지**됩니다. 다만 하위의 비용 범위 확인 질문은 해결될 수 있으므로 전체 순위가 모두 그대로라는 뜻은 아닙니다. “Top-3 변경 없음”을 실패나 무반응으로 설명하지 말고, 상태·요건의 변화와 순위의 변화를 구별해 보여줍니다.

## 4:20–5:10 — T4 해결되는 질문과 남는 위험

`nb_update_t4`의 Birch 계약·검수·수금 및 소유관계 자료를 확인하고 승인합니다. Birch 계약과 실행 요건이 해결되는 반면, Aster와 Birch가 동일 지배집단이어서 독립된 두 고객이라는 요건이 충족되지 않는 점을 확인합니다. Aster 수익성·잔여 수금·배포 역량 등에 대한 미해결 질문을 보여줍니다.

`Adaptive analytics`에서 순위 전후 비교와 Bayesian/EIG 영역을 확인합니다. 확률의 가정 출처와 정보량 단위 bits를 설명합니다. 가정이 없는 계산은 `Unavailable`로 남으며 EIG를 제품 점수에 추가하지 않습니다.

## 5:10–6:00 — 분석가 승인 후 결과 내보내기

`Screening & export`에서 `Screening Memo · Word` 또는 `Screening Memo · Markdown`을 선택합니다. 현재 Snapshot과 미확인 사항을 읽고 `I reviewed this snapshot and approve this export.`를 체크합니다. 표시된 revision에 대해 `Ready to download` 안내가 나온 뒤 `Approve & download`를 누릅니다. 화면이 갱신 중이라는 안내가 나오면 완료된 화면을 읽고 다시 승인합니다.

다음으로 `DD Request List · Excel`을 선택하고 다시 검토·승인하여 내려받습니다. 다운로드된 파일에서 원문 참조, 승인된 Snapshot, 남은 질문과 합성 예비 검토의 범위를 확인합니다. 내보내기 승인을 투자 승인으로 표현하지 않습니다.

## 6:00–7:00 — 반려·격리·다른 사업모델 확인

시간에 따라 아래 중 한 가지를 선택합니다.

| 보조 시연 | 진행 | 확인할 점 |
|---|---|---|
| 반려 | 새 탭에서 Northstar를 열고 T1의 이유를 적어 `Reject update` | 승인 전 Top-3와 Snapshot이 유지되고 반려 이력이 남음 |
| 세션 격리 | 독립 브라우저 프로필 또는 시크릿 창에서 같은 주소 접속 | 기존 창의 승인 진행이 새 세션에 전파되지 않음 |
| 제조업 | `Manufacturing case`에서 `mf_update_t1` 검토·승인 | 실물 재고 수량 확인이 재고 평가·회수 가능성·운전자본 해소까지 증명하지 않음 |
| 반증으로 재개 | `Lumen · conflict review`에서 이벤트 검토·승인 | 기존에 해결되었던 갱신 질문이 반증으로 다시 열림 |

이 보조 시연을 했다는 것만으로 자동화된 보안 또는 브라우저 테스트 전체를 실행한 것으로 보고하지 않습니다. 검증 결과는 구현 보고서의 실제 실행 기록을 따릅니다.

## 실제 지원하는 단계

| 사례 | 이벤트 | 용도 |
|---|---|---|
| Northstar 심화 `nb` | `nb_update_t1` | Aster 계약 |
| Northstar 심화 `nb` | `nb_update_t2` | Aster 검수·첫 수금 |
| Northstar 심화 `nb` | `nb_update_t3` | 비용 범위 완성·수익성 반증·Top-3 유지 |
| Northstar 심화 `nb` | `nb_update_t4` | Birch 계약·실행·공통 소유관계 |
| 제조업 `mf` | `mf_update_t1` | 재고 수량 대사 증빙 |

제조업에 존재하지 않는 T2–T4를 시연했다고 설명하지 않습니다. 초기 단계 T0는 초기 상태이며 추가 승인 이벤트가 아닙니다. 반려 후 동일 이벤트를 승인하는 다른 경로를 보려면 `Reset demo`로 새 진행을 시작합니다.

## 발표에서 구분할 표현

- **구현된 기능:** 합성 원문의 위치 검증, 결정론적 질문 순위, 인간 검토, 승인 전후 변화, 가정 기반 Bayesian/EIG, 템플릿 기반 보고서.
- **실행한 범위만 보고할 항목:** 전체 회귀 테스트, 브라우저 화면·키보드·세션 격리 검증, 운영체제별 실행.
- **이번 데모의 결과가 아닌 것:** 실제 LLM 분석 성능, 실제 기업에 대한 투자 성공확률, 완성된 FDD, 공개 운영 배포.
