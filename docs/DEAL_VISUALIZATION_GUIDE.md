# 거래 구조·FDD 시각화

왼쪽의 **거래 구조·FDD 시각화 ↗**에서 연다. 기존 5단계와 원문 자료실은 유지하며 어느 단계에서든 시각화로 이동할 수 있다. 워크플로 단계를 클릭하면 원래 화면으로 돌아간다.

## 1. 자금 흐름

Sources(투자자·대주 등) → 자금 계정/SPC → Uses(매도인·상환처·비용·유보 현금)의 Sankey 형태로 표시한다. 선의 두께는 금액에 비례하고 각 항목은 클릭·키보드로 편집할 수 있다. 도표와 전체 명세를 함께 제공한다.

Sources − Uses가 양수면 미배분, 음수면 사용 계획 대비 부족분이다. 자동으로 가상 조달이나 잔여 현금을 채워 맞추지 않는다. 중앙 계정에서 자금이 합쳐지는 예산 흐름으로, 특정 투자자 자금이 특정 용도로 지정됐다는 의미는 아니다. 금액 일치와 조달 확약·집행 완료는 구분한다.

등록된 실제 사례는 이미 작성된 예산을 읽기 전용으로 바로 연결한다. 편집·저장하면 그 예산에서 시작하는 별도 시나리오를 저장한다. 비어 있는 경우 **기존 사례 자금표 연결**도 제공한다. 총액·중간 사용·잔여가 대사되는 경우에만 연결하고, 조달자는 미분류로 남긴다. CB 조건이나 확약을 문서 제목으로 추론하지 않는다. 기존 시각화는 삭제하지 않는다.

## 2. 조달·BS 대변

각 상품에 발행 주체, 상품 종류, 조달 현금, 기준일 장부금액, 계약 조건, 근거를 기록한다. 부채·자본·복합·미확정을 선택하고, 복합 상품은 부채 부분과 잔여 자본 부분을 분리한다. 선택한 발행 주체와 다른 법인은 합산하지 않는다.

CB·RCPS의 이름만으로 회계 분류를 확정하지 않는다. 분류를 입력하려면 검토한 계약 조건을 기록한다. 조달 현금과 장부금액은 발행비용·할인·전환권 등에 따라 다를 수 있으므로 같은 값으로 자동 대사하지 않는다. 회계 분류의 기준은 [IAS 32](https://www.ifrs.org/issued-standards/list-of-standards/ias-32-financial-instruments-presentation/)를 참고한다.

차변에는 선택 입력한 자산 총액, 대변에는 입력한 조달 항목을 표시한다. **동일 주체·기준일의 부채·자본 전체 입력 확인**, 미확정 없음, 자산 총액 입력을 충족한 경우에만 BS 차이를 표시한다. 전체 입력 전에는 부분 조달 구성이다. 음수 자본은 오해를 줄이기 위해 구성비 막대 대신 금액으로 표시한다. 거래상 Net Debt 정의와 회계상 부채 분류는 별도다.

## 3. QoE·NWC·Net Debt 워터폴

| 구분 | 기준·하위 항목 | 조정 부호 |
|---|---|---|
| QoE | 손익 기간, 보고 EBITDA → 일회성 비용/수익, Run-rate, 회계정책 등 | EBITDA 증가 + / 감소 − |
| NWC | 기준일·영업 범위, 매출채권·재고·매입채무·미지급비용 등 | NWC 증가 + / 감소 − |
| Net Debt | 기준일·거래상 정의, 차입금·현금·리스·채무 유사항목 등 | Net Debt 증가 + / 감소 − |

조정 전 금액과 각 조정 금액으로 조정 후 값을 계산한다. 제안·검토 반영·제외 상태를 제공하며 기본 그래프는 검토 반영 항목만 포함한다. 제안 포함 미리보기는 저장 상태를 바꾸지 않는다. 반영은 시나리오 검토 상태로서 증빙 승인·확률 갱신·실제 회계 전표 반영이 아니다.

상위 8개 절대금액 조정과 나머지 합계를 표시하고 모든 항목은 명세에서 확인한다. 0·음수·순현금도 처리하며 기준값 공란을 0으로 대체하지 않는다. 그래프의 숫자·축·명세는 동일 단위다. 회색은 시작/종료, 파랑은 증가, 주황은 감소다. 각 워터폴은 독립 SVG로 저장할 수 있다.

## 4. 지분가치 연결

`지분가치 = EV − Net Debt + (NWC − NWC 목표값)`

EV 고정 또는 EBITDA×배수 모드를 선택한다. 배수 모드에서는 QoE 변화×배수를 EV 변화로 연결한다. 고정 EV에서는 QoE 변화가 가격에 자동 가산되지 않는다. Net Debt 증가는 지분가치 감소, NWC 증가는 증가 방향이다. 기간·기준일·범위와 필요한 기준 금액이 있어야 계산한다. 이는 계약상 정의와 세금·추가 가격 조정 등을 단순화한 시나리오다. [FDD의 주요 분석 영역](https://www.pwc.com/us/en/services/consulting/deals/joint-ventures-alliances/financial-due-diligence.html), [NWC·Net Debt 가격 조정 참고](https://www.rsm.global/service/financial-due-diligence).

NWC·Net Debt 항목의 중복 검토 키를 입력한다. 같은 경제 항목이 양쪽에 반영되거나 키가 누락되면 해당 가격 브리지를 보류한다. 키가 다르다고 의미적 중복이 완전히 검출되는 것은 아니므로 담당자 검토가 필요하다.

## 데이터·저장·시연

값은 현재 프로젝트의 단위 하나를 사용한다. 기존 금액이 있으면 단위 변경을 거절하며 환율·단위 재해석을 자동 적용하지 않는다. 항목마다 입력 근거와 선택 원문을 기록하고 조정에는 실사 질문도 연결할 수 있다. 전체 입력과 버전별 스냅샷, 검토 보고서 HTML·JSON에 기록한다. 기존 실제 사례는 명시적으로 저장/가져오기 전까지 바꾸지 않는다.

빠른 체험은 **합성 검증 사례 열기**로 새 프로젝트를 만든다. 기존 실제 프로젝트를 합성 값으로 덮어쓰지 않는다. 예시 수치는 Sources/Uses 300, 장부 부채 170·자본 130, QoE 30→32, NWC 25→22, Net Debt 50→55이며 배수 8배·NWC 목표 22에서 지분가치 193→201이다. 제안 포함 시 지분가치는 193이다. 이 값은 실제 기업 분석 결과가 아니다.

검증: `python -m pytest tests/rules/test_deal_visuals.py tests/rules/test_rules_browser.py -q`. 금액 대사·복합 분류·발행 법인 분리·누락 값·상태별 조정·가격 영향 부호·중복 방지·증빙/확률과의 분리 및 화면 크기별 골격을 검사한다.
