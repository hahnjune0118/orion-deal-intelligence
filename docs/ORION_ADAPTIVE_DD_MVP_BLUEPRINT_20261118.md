# Orion Adaptive DD MVP Blueprint

작성일: 2026-11-18
상태: 제품·구현 설계안. 이 문서 작성으로 현재 대시보드나 분석 엔진을 변경하지 않는다.

## 1. 제품의 중심

**투자자료에서 검증할 가설을 만들고, 지금 가장 가치 있는 실사 질문을 추천하며, 새 증거가 들어오면 다음 질문을 바꾸는 근거 기반 실사 보조 도구.**

FDD 전 과정의 자동화·회계 조서 플랫폼을 MVP 목표로 삼지 않는다. IB·PE·Big 4 담당자가 초기 투자 검토와 실사 질문 설계에 사용할 수 있는 좁은 업무부터 완성한다.

사용자가 매번 확인할 결과는 세 가지다.

1. **지금 무엇이 불확실한가?** — 가설과 현재 증거.
2. **다음에 무엇을 물어야 하는가?** — 추천 질문 3개와 선정 이유.
3. **새 자료 때문에 무엇이 달라졌는가?** — 가설·질문·순위의 전후 차이.

제품의 차별점은 많은 차트나 종합 재무 분석이 아니라 **근거를 추적할 수 있는 적응형 질문 루프**다.

## 2. 첫 사용 사례와 범위

- 초기 검증 대상: 자료가 있는 B2B 소프트웨어·서비스 기업의 매출 지속성. 한 프로젝트에 한 기업을 둔다.
- 첫 검증 주제: 반복매출의 정의·실재성, 고객 집중과 갱신, 계약·인식 매출·수금의 일관성.
- 초기 기본값 제안: 가설 3~5개, 질문 후보 10~15개, 다음 추천 질문 3개. 설정이 아니라 제품의 초기 운영 규격으로 두고 파일럿에서 조정한다.
- 문서에 맞춰 가설을 생성한다. 모든 기업에 ARR·NRR 등 SaaS 지표를 억지로 적용하지 않는다.
- 초기 필수 입력: 텍스트 PDF·DOCX·PPTX. 스캔·암호화·복잡한 표 등은 검토 필요로 표시한다. XLSX의 선택 시트·셀 단위 읽기는 이후 작은 확장으로 분리하고 완전한 Excel 모델 해석은 제외한다.
- 경영진 답변은 텍스트와 첨부 증빙을 함께 등록할 수 있다. 답변만 수령한 것과 원천 검증을 마친 것을 구분한다.

## 3. MVP에 남길 것과 기본 화면에서 뺄 것

| 남길 핵심 | MVP 기본 흐름에서 제외·보관 |
|---|---|
| 자료 수집·분석과 원문 인용 | 월별 원장 대사·계정 매핑 업무 화면 |
| 투자 가설과 반증 조건 | QoE·NWC·순차입금 조정 원장 |
| 실사 질문과 요청 증빙 | EV–Equity bridge·SPA 메커니즘 |
| 중요도·정보가치 평가 | 작성자·검토자 결재 관리 체계 |
| 새 증거 검토와 질문 갱신 | 종합 FDD 보고서 제작·회계 조서 입력 |
| 프로젝트 저장·원문 확인·질문표 내보내기 | 별도 PE/IB/Big 4 화면 모드, 복수 목록/Matrix/체크리스트 모드 |

기존 기능과 시각화는 삭제하지 않는다. 현재 작업을 보존한 별도 버전으로 남기고, 새 MVP의 기본 메뉴에서는 노출하지 않는다. 재사용할 시각화는 해당 핵심 단계에서 사용한다. 이 문서는 기존 시각화·표를 일괄 수정하거나 삭제할 권한으로 해석하지 않는다.

## 4. 단 하나의 5단계 흐름

| 단계 | 핵심 동작 | 사용자에게 보여 줄 결과 | 완료 조건 |
|---|---|---|---|
| 1. 투자자료 분석 | 자료 등록, 추출, 검색, 주요 주장·수치·공백·상충 항목 식별 | 근거가 연결된 자료 분석표 | 처리 범위와 실패·누락이 표시되고 모든 인용을 열 수 있음 |
| 2. 투자 가설 생성 | 자료 기반 검증 가능한 가설·반대 가설 제안 | 가설 카드와 반증 조건 | 담당자가 가설·정의·기간·범위를 확정 |
| 3. 실사 질문 생성 | 가설별 미해결 사항을 확인하는 구체적 질문 생성 | 질문 목록·요청 증빙·판정 기준 | 중복 제거와 담당자 검토를 통과 |
| 4. 중요도 평가 | 재무 중요성, 증빙 공백, EIG, 확보 가능성을 평가 | 다음 질문 3개와 순위 이유 | 추천 정책과 가정이 공개되고 미계산 값이 구분됨 |
| 5. 새 증거 반영 | 답변/자료 연결, 지지·반박·불충분 판정 검토, 사후확률·질문 갱신 | 승인 전후 비교와 다음 추천 | 적용 승인 후 새 스냅샷을 저장하고 변경 이유를 남김 |

5단계에서 4단계로 돌아와 다음 질문을 선택한다. 필요하면 가설 정의를 수정한 새 버전을 만들고 2·3단계로 돌아간다. 매번 모든 질문을 다시 만드는 방식은 사용하지 않는다.

## 5. 대시보드 배치

### 공통 틀

- **왼쪽:** 프로젝트/기업, 자료 기준일, 5개 단계. 역할별 보기 선택과 8단계 FDD 메뉴는 MVP 기본 화면에서 제외한다.
- **중앙:** 현재 단계의 주 작업 한 가지. 목록은 한 가지 방식으로 유지한다.
- **오른쪽 위:** 선택한 가설·질문·증거의 상세와 원문 인용. 모든 단계에서 같은 폭·글자 크기를 사용한다.
- **오른쪽 아래:** 항상 보이는 프로젝트 자료 목록. 기존 파일 형식 아이콘·검색·원문 위치 기능을 재사용한다.
- **상단:** 프로젝트 이름, 현재 버전, 저장/실행 상태. RAG·EIG·EVSI 설정을 여러 독립 메뉴로 늘어놓지 않는다.

```text
왼쪽                    중앙                         오른쪽
프로젝트 / 기준일       현재 단계 제목               선택 항목·원문
1. 투자자료 분석        [핵심 작업 / 승인·실행]       근거·가정·변경 이유
2. 투자 가설 생성       표 또는 카드                 ───────────────
3. 실사 질문 생성       단계에 맞는 시각화 1~2개     프로젝트 자료
4. 중요도 평가                                       검색·유형·파일
5. 새 증거 반영
```

### 단계별 화면과 시각화

| 단계 | 주 화면 | 필요한 시각화 |
|---|---|---|
| 자료 분석 | 주장 / 수치·정의·기간 / 출처 / 공백·상충 표 | 자료 처리·검증 상태 요약. 자료 수를 실사 완료율로 표시하지 않음 |
| 가설 생성 | 가설별 주장·반대 가설·지지/반박 근거·반증 조건 카드 | 가설별 현재 확률과 가정 범위. 수치가 없으면 미설정 |
| 질문 생성 | 질문 / 연결 가설 / 요청 증빙 / 해소 조건 목록 | 별도 차트보다 질문과 근거 연결을 우선 |
| 중요도 평가 | 다음 질문 3개 + 전체 후보 목록 | 순위 구성요인 막대, 중요도–EIG 산점도 중 필요한 것만 사용 |
| 새 증거 반영 | 새 증거와 원문 / 적용 전후 / 승인 | 가설 확률 전후와 질문 순위 이동. 로그 오즈 워터폴은 상세 보기에서 제공 |

기본 질문 행은 `질문 · 연결 가설 · 중요도 · EIG · 처리 상태` 정도로 제한한다. EVSI·시간·비용·세부 확률은 선택한 질문의 오른쪽 ‘평가 근거’에서 확인한다.

## 6. RAG: 자료를 근거 있는 가설·질문으로 연결

RAG는 검색한 외부 자료를 생성 과정에 제공하는 구조다. 이를 Orion에서는 **현재 프로젝트의 검증된 원문 구간을 찾아 가설·질문 생성의 근거로 전달하는 역할**로 사용한다. 검색 결과가 있다는 사실만으로 주장이 참이라고 판단하지 않는다. [Lewis et al., 2020](https://arxiv.org/abs/2005.11401)

처리 순서:

1. 원본 파일과 해시·버전을 저장한다.
2. 문단·페이지·슬라이드·표 구조를 보존해 원문 구간을 만든다.
3. 문서명·버전·위치·기간·통화·단위와 함께 프로젝트별로 색인한다.
4. 가설/질문에 필요한 구간을 키워드와 의미 검색으로 찾는다.
5. 해당 구간만 모델에 제공해 구조화된 주장·가설·질문 초안을 받는다.
6. 인용이 실제 파일과 위치에 대응하는지 검증한다. 대응하지 않으면 생성 실패/검토 필요로 남긴다.

MVP에서는 기존 키워드 검색을 기준선으로 쓰고 의미 검색을 더한 단순한 혼합 검색을 평가한다. 별도 지식 그래프나 다중 에이전트 구조는 필수로 삼지 않는다.

동일 원문의 재인용은 독립 근거가 아니다. ‘자료에 기재된 주장’, ‘확인된 계산’, ‘모델의 해석’, ‘추가 검증 필요’를 구분한다. 업로드 문서의 지시문은 데이터로만 취급한다.

현재 파서는 문서·페이지·텍스트 길이 제한이 있다. 긴 사업보고서는 페이지 묶음 단위로 처리하되 원본 페이지 번호·해시를 유지하고 전체 처리 여부를 표시한다. 일부 50페이지만 읽은 결과를 전체 문서 분석 완료로 표시해서는 안 된다.

## 7. 투자 가설: 계산 가능한 검증 대상으로 좁힌다

가설은 ‘성장성이 높다’보다 **범위·기간·관측 기준이 있는 명제**로 만든다.

예: ‘2025년 반복매출로 분류된 고객 계약은 해당 기준일에 유효하고, 해지·단발성 매출을 제외해도 회사가 제시한 반복매출 정의를 충족한다.’

가설 카드 필수 항목:

- 가설과 반대 가설, 대상 기업·기간·지표 정의.
- 현재 지지·반박 근거와 자료 공백.
- 어떤 증거가 가설을 지지하거나 반박하는지에 대한 판정 기준.
- 확인할 질문과 요청 자료.
- 사전확률 및 우도 가정의 출처·설정자·버전·검토 상태.

첫 MVP는 질문 한 개에 주된 이진 가설 하나를 연결한다. 부차적인 가설은 참조로 남긴다. 관련 가설 여러 개의 EIG를 단순 합산해 정보가치를 부풀리지 않는다.

## 8. Bayesian 업데이트: 증거가 들어왔을 때 믿음을 갱신

주된 가설 H에 대해 검토된 확률 가정과 승인된 새 증거 E가 있을 때 계산한다.

`P(H|D,E) = P(E|H,D) P(H|D) / [P(E|H,D) P(H|D) + P(E|¬H,D) P(¬H|D)]`

D는 이미 반영한 증거다. 현재 사후확률을 다음 업데이트의 사전확률로 사용한다. 문서 검색 유사도·LLM 자신감·질문 중요도 점수를 확률로 바꿔 넣지 않는다.

- LLM은 증거의 의미·관련 가설·판정 후보를 제안한다. 확률 계산과 업데이트 적용은 계산 모듈과 담당자 검토가 맡는다.
- 확률 가정은 전문가 시나리오, 관측 자료, 이후 검증 자료 등 출처를 명시한다. 첫 버전은 ‘가정 기반 검토 확률’이며 실제 투자 성공확률로 표현하지 않는다.
- 사전확률을 만들 때 사용한 자료를 새 독립 증거처럼 다시 곱하지 않는다. 초기 증거와 이후 증거의 경계를 기록한다.
- 동일 문서·인용·원천에서 파생한 자료는 중복/의존 그룹으로 관리한다. 계약·검수·수금도 자동으로 독립이라고 가정하지 않는다.
- 상관 증거는 검토된 조건부 모형이 있을 때만 반영한다. 모형이 없으면 갱신을 보류하고 이유를 보여 준다.
- 수정·철회된 증거는 역방향 보정 숫자를 임의로 더하지 않고 승인 이력을 재생해 계산한다.
- 답변 미수령·자료 부족은 곧바로 반증이 아니다. 확률을 유지하거나 모형상 정의한 결과로만 처리한다.
- 사전확률·우도 가정을 바꾸면 새 가정 버전으로 재계산하고 과거 결과를 덮어쓰지 않는다.

단순 검증 예시: 사전확률 0.30, 관측한 긍정 결과의 우도 `P(+|H)=0.80`, `P(+|¬H)=0.20`이면 사후확률은 약 **0.6316**이다. 이는 계산 시나리오이며 실제 기업에 대한 확률 추정이 아니다.

## 9. EIG: 질문을 하기 전 기대하는 불확실성 감소

`EIG(q|D) = Entropy(H|D) − Σ_y P(y|D,q) Entropy(H|D,y,q)`

이진 가설의 엔트로피는 `−p log₂(p) − (1−p) log₂(1−p)`이며 EIG 단위는 bits다. 질문의 가능한 답변을 모두 고려하는 관측 전 기대값이다. 정보량을 실험 설계의 기준으로 삼는 연구를 참고한다. [Kleinegesse & Gutmann, 2020](https://proceedings.mlr.press/v119/kleinegesse20a.html)

질문마다 답변 결과와 `P(y|H,D,q)`, `P(y|¬H,D,q)`를 설정한다. 각 가설 조건에서 결과별 확률 합은 1이어야 한다. 증빙 불충분 결과를 넣는다면 그 결과의 우도도 정의한다. 불충분을 무조건 부정 결과로 취급하지 않는다.

- 답변 모형·가정이 없으면 EIG는 **미계산**이다. 0으로 바꾸지 않는다.
- 동일 예시에서 긍정/부정 결과가 전부인 질문의 EIG는 약 **0.2361 bits**다.
- 실제 관측 한 번은 불확실성을 늘릴 수도 있다. EIG가 양수라고 모든 관측 뒤 확률이 높아지거나 엔트로피가 감소해야 하는 것은 아니다.
- 새 증거가 반영되면 남은 질문의 EIG를 현재 분포에서 다시 계산한다. 이미 해소한 증빙을 다시 요청하는 질문은 추천에서 제외한다.

## 10. EVSI: 정보가 의사결정을 얼마나 개선하는가

EIG는 학습량이다. EVSI는 새로운 정보를 보고 더 나은 행동을 선택해서 얻는 **기대 의사결정 가치**다. 같은 값이나 이름으로 취급하지 않는다. [ISPOR VOI 방법론 보고서](https://pmc.ncbi.nlm.nih.gov/articles/PMC7373630/)

`EVSI(q|D) = Σ_y P(y|D,q) max_a E[U(a,H)|D,y,q] − max_a E[U(a,H)|D]`

`질문 순가치 = EVSI − 증빙 확보 비용 − 별도 정의한 지연 비용`

MVP 적용 범위:

- 선택 질문의 상세 화면에서 **가정 기반 의사결정 시나리오**로 제공한다. 별도 EVSI 업무 메뉴는 만들지 않는다.
- 첫 모형은 주된 이진 가설 하나와 행동 두 가지로 제한한다. 사용자는 행동과 각 상태의 손익/효용 표, 통화·단위, 질문 비용을 명시한다.
- 실제 의사결정 모형을 정의하기 어렵다면 EVSI를 미계산으로 둔다. 투자금·예상 손실률 등을 모델이 임의로 채우지 않는다.
- 금액 효용이 없으면 금액 EVSI를 표시하지 않는다. ‘점수형 효용’으로 계산했다면 단위를 점수라고 명시한다.
- 학습해도 최적 행동이 바뀌지 않는 질문은 EIG가 양수여도 EVSI가 0일 수 있다.
- gross EVSI와 순가치를 나눠 보여 준다. 같은 비용을 효용 표와 질문 비용에서 두 번 빼지 않는다.
- 실데이터 MVP 화면과 별도로, 입력·결과가 검증된 EVSI 예시 한 개를 반드시 제공한다. 공식 거래가치·실제 투자 수익 예측으로 표시하지 않는다.

전체 거래 가치평가나 의사결정 자동 승인은 범위에 넣지 않는다. EVSI는 별도 손익 가정을 검토할 수 있는 경우에만 의사결정 보조로 사용한다.

## 11. 중요도와 추천 순위 정책

기본 화면에는 중요도·EIG·추천 순위를 구분해 표시한다. 중요도는 문제가 사실일 때 투자 판단에 미치는 영향이고, EIG는 그 질문으로 배우는 양이다.

첫 MVP의 추천 정책 제안 `adaptive-dd-v1`:

1. 필수 확인·중대한 경고 질문은 정보량 점수와 관계없이 별도 상단에 둔다.
2. 나머지 질문은 검토된 중요도, 증빙 공백, 확보 가능성, 현재 EIG로 추천한다.
3. 출발 가중치 제안: 중요도 0.35 / 증빙 공백 0.25 / EIG 0.25 / 확보 가능성 0.15. 이는 파일럿에서 비교·조정할 제품 가정이며 검증된 금융 공식이 아니다.
4. 입력을 명시적 기준으로 0~1에 정규화한다. 이진 EIG는 최대 1 bit 범위에서만 이 정책에 사용한다. 모형이 바뀌면 정규화 규칙도 버전 관리한다.
5. EIG가 없으면 해당 항목을 제외하고 나머지 가중치를 재정규화해 ‘정성 추천·잠정’으로 표시한다. 입력 없는 중요도까지 근거 없이 숫자를 채우지는 않는다.
6. 시간·외부 비용은 추가 정보로 표시하고 예산·기한 제약과 동률 해소에 사용한다. 확보 가능성에 이미 포함한 비용을 다시 가산점/감점으로 중복 적용하지 않는다.
7. EVSI는 모형이 설정된 질문끼리의 시나리오 비교로 제공한다. bits·원·정성 점수를 그대로 더한 종합 점수는 만들지 않는다.

현재 공식 점수 `9×gap + 8×materiality + 3×obtainability`는 기존 버전의 비교 기준으로 보관한다. 새 MVP에서는 **새 정책 버전이 실제 추천 목록을 결정**해야 한다. Bayesian/EIG 차트만 붙이고 기존 순위를 그대로 두는 구현은 이 MVP의 완료로 보지 않는다.

화면에는 ‘왜 지금 이 질문인가’, ‘직전 대비 무엇 때문에 순위가 바뀌었나’, ‘가정을 바꾸면 순위가 뒤집히나’를 설명한다. 기본 순위는 하나이며 정책 선택 메뉴를 여러 개 노출하지 않는다.

## 12. 새 증거 반영 루프

1. 질문에 답변 또는 새 파일을 연결한다.
2. RAG가 해당 질문·가설과 관련된 구간을 찾는다. 연결 대상과 원문 위치를 검증한다.
3. AI가 지지·반박·불충분 판정 후보, 중복/상충 가능성, 영향을 받는 가설을 제안한다.
4. 담당자가 증거의 의미·의존 그룹·확률 모형을 확인한다. 단순 파일 수령을 사실 승인으로 취급하지 않는다.
5. 승인 전 미리보기에서 확률·질문 상태·순위의 변경안을 확인한다.
6. 적용 승인 후 새 증거/가설/추천 스냅샷을 원자적으로 저장한다. 실패하면 이전 버전이 유지된다.
7. 관련 가설과 남은 질문만 재평가한다. 해소·불충분·재개·새 질문·추천 유지의 이유를 남긴다.
8. 원하면 이전 버전과 비교한다. 증거 반려 시 현재 확률과 추천은 바뀌지 않는다.

새 질문은 고유 ID를 받는다. 기존 질문의 표현 수정은 같은 질문의 새 버전으로, 검증 대상 자체가 달라진 경우는 새 질문과 이전 질문의 관계로 기록한다. 질문 수를 늘리는 것을 개선으로 평가하지 않는다.

## 15. 구현 순서와 단계별 산출물

### A. MVP 화면과 경계 확정

현재 미커밋 작업까지 포함한 복원 가능한 스냅샷을 확보한 후 별도 구현 브랜치를 사용한다. 5단계 메뉴·단일 질문 목록·현재 추천 3개·증거 전후 비교를 우선 배치한다. 이 단계만으로 실제 AI 기능 완료라고 보고하지 않는다.

### B. 실제 자료 → 근거 있는 가설·질문

프로젝트 저장, 업로드·파싱·원문 인용 검증, 검색 평가, 실제 모델 기반 구조화된 가설/질문 생성까지 연결한다. 인용 없는 가설·질문과 잘못된 기간·단위는 검토 대상으로 분리한다. 이 단계가 첫 번째 실사용 가능한 제품 조각이다.

### C. Bayesian/EIG → 실제 다음 질문 추천

담당자가 검토한 가설·답변 모형을 연결하고, 새 증거 적용 미리보기·승인·재생·추천 정책을 완성한다. 세 번의 증거 라운드를 끝까지 수행해 추천 이유가 실제로 바뀌는지 확인한다.

### D. EVSI 시나리오와 내보내기

2행동×2상태 결정표, 질문 비용, 민감도 분석을 질문 상세에 연결한다. 가정이 없는 실제 프로젝트는 미계산으로 유지한다. 질문표·근거·가정·업데이트 이력을 하나의 간단한 산출물로 내보낸다.

### E. 파일럿 검증

합성 정답 시나리오와 실제 공개 기업자료를 나눠 검증한다. 실제 기업자료는 근거·질문 품질 검증에 사용하며 가설의 참/거짓 정답이 자동 확보된 것으로 취급하지 않는다. 대시보드 장식보다 추천의 타당성·재현성·실제 검토 시간 절감을 기준으로 개선한다.

## 16. 완료 기준

- 자료 등록부터 추천 갱신까지 5단계를 한 프로젝트에서 끝까지 수행할 수 있다.
- 사용자에게 제시하는 모든 인용 참조가 원본 위치·버전에 대응한다. 이는 주장의 진실성 100%를 뜻하지 않는다.
- 회사·시점·기간·통화·단위가 다른 자료를 몰래 합치지 않는다. 미제공·처리 실패는 숨기지 않는다.
- 3개 이상의 검증 시나리오: 기존 질문 유지, 순위 역전, 해소 후 다른 질문 추천. 무관한 증거에 순위를 억지로 바꾸지 않는다.
- 같은 증거 재제출, 상관 자료, 증거 반려·철회, 잘못된 우도, 불충분 답변에서 잘못된 확률 갱신이 없다.
- EIG는 독립 계산식으로 교차 검증하고 `0 ≤ EIG ≤ 현재 엔트로피`를 확인한다.
- 같은 행동·효용 모형에서 `0 ≤ EVSI ≤ EVPI`, 비정보적 질문의 EVSI=0, 비용 차감과 의사결정 불변 시나리오를 검증한다.
- 가정이 없는 EIG/EVSI는 미계산이며 순위의 잠정성·변경 이유를 확인할 수 있다.
- 초기 파일럿에서 기업 2곳·검토 질문 최소 30건을 대상으로 검색 적합성, 인용의 주장 뒷받침 여부, 질문의 구체성·중복·실무 유용성을 사람이 평가한다. 수치 목표는 파일럿 전에 정한다.
- 모델 호출 전후 비용·시간과 수작업 대비 검토 시간을 측정한다. 임의의 성능 개선율을 제시하지 않는다.
- 실제 확률 보정 성능을 주장하려면 별도의 관측 결과/정답 자료와 교정 평가가 필요하다. 합성 산술 테스트 통과로 대체하지 않는다.
- 앱을 다시 열어도 승인 이력·질문 버전·원문 참조가 유지되고 같은 입력·정책·가정으로 수치 계산과 추천을 재현할 수 있다. 생성 결과는 저장된 실행 버전을 기준으로 추적한다.

## 17. 제품 데모의 한 문장

**‘이 자료에서 무엇을 의심해야 하고, 지금 어떤 질문을 해야 하며, 새로운 답변 때문에 다음 질문이 왜 바뀌는지 보여드립니다.’**

이 시연 하나가 근거와 계산까지 일관되게 작동하는 것이 MVP의 출시 기준이다.
