# Orion 공통 작업 화면 개편 Blueprint

작성일: 2026-11-18 · 기준 커밋: ea07cc4

## 1. 목표와 범위

IB·Big 4·PE의 FDD 업무를 지원하는 목적에 맞춰, **왼쪽에서 설정하고 업무를 선택 → 중앙에서 분석 → 오른쪽에서 근거와 자료 확인**으로 시선을 정리한다. 이번 문서는 구현 청사진이다. 애플리케이션 화면 변경은 아직 적용하지 않았다.

8단계 FDD 업무와 질문·증빙 보조 도구 모두 동일한 화면 틀을 사용한다. 역할별 보기와 페이지별 내용은 달라져도 상단·왼쪽·오른쪽 패널의 위치와 크기는 동일하게 유지한다.

## 2. 현재 화면 확인 결과

로컬 Chromium에서 8개 FDD 화면과 9개 보조 도구 화면을 각각 열었다. 1440×1000에서 FDD 8단계 × 3개 업무 관점, 보조 도구 9개, 1920×1080에서 FDD 8단계를 합쳐 41개 상태를 측정했다. FDD 화면은 문서 스크롤 전후 위치도 측정했다. 이는 현재 구조 조사이며, 개편 후 합격 판정은 아니다.

| 확인 항목 | 실제 관찰 | 설계에 반영할 내용 |
|---|---|---|
| 업무 관점 | FDD 중앙 제목 오른쪽의 `fw-role`에 위치 | 왼쪽 상단의 상시 설정으로 이동 |
| 질문·증빙 도구 | 전역 헤더 오른쪽 메뉴 | 왼쪽 상단에 고정 진입점 배치 |
| 원문 패널 | 접기 버튼과 2열 전환 규칙이 존재 | 접기 기능과 전환 규칙 제거 |
| 자료 목록 | 초기 상태에서 목록이 보이지 않고 헤더 버튼으로 펼침 | 오른쪽 하단의 상시 자료 영역으로 변경 |
| 단계 이동 | 왼쪽 8단계와 중앙 8단계가 중복 | 왼쪽 단계 선택만 유지 |
| 패널 외곽 | 1440px에서 측정한 17개 화면의 오른쪽 폭은 420px로 동일 | 폭보다 스크롤·내부 구조·중앙 시작점까지 함께 통일 |
| 중앙 본문 | 기본 FDD 본문 y=308px, 재무 분석은 y=374.5px | 제목·도구줄·분석 탭 영역의 높이를 공통화 |
| 스크롤 | 개요에서 상단 y=0→−75px, 오른쪽 y=76→16px 이동 관찰 | 문서 전체 스크롤 대신 패널 내부 스크롤 적용 |
| 스타일 | `orion.css`, `studio.css`, `zz_readability.css`, `zzz_uniform.css`, `zzzz_fdd.css`에 공통/페이지별 규칙 분산 | 공통 화면 틀의 치수·타이포그래피 규칙을 한곳에서 관리 |

측정 자료: `build/frame-blueprint-audit/measurements.json`. 해당 폴더에 17개 화면의 캡처도 보관했다. 보조 도구의 모든 상태 및 작은 화면에서의 개편 후 검증은 아래 검증 계획에 따라 별도로 수행한다.

│ 투자 대상      ├──────────────────────────────┤                 │

### A. 왼쪽 상단: 초기 설정과 도구

- 순서는 **투자 대상 → 업무 관점 → 분석 기간 → 질문·증빙 도구 → FDD 8단계**로 고정한다.
- 업무 관점은 `PE / IB / Big 4`의 선택형 컨트롤로 계속 보이게 한다. 이는 분석 보기 설정이며 사용자 권한·소속 인증으로 표시하지 않는다.
- 초기 설정은 어느 업무 화면에서도 유지한다. 기존 `fw-role`, `fw-period`를 공통 왼쪽 영역으로 옮겨 같은 값을 사용하고 중복 컨트롤은 만들지 않는다.
- 기간은 왼쪽에서 선택하고 중앙에는 현재 적용 기간을 텍스트로 표시한다. 보조 도구 중 기간 필터를 사용하지 않는 기능에는 적용되지 않음을 표시한다.
- `질문·증빙 도구` 진입점은 설정 바로 아래에 상시 표시한다. 클릭하면 왼쪽 영역 안에서 도구 항목이 펼쳐진다. 펼쳐지는 부분만 내부 스크롤하며 설정 및 FDD 메뉴를 화면 밖으로 밀지 않는다.
- 도구 사용 중에도 FDD 8단계 메뉴는 남겨 두고, 선택한 도구를 별도로 강조한다. FDD와 보조 도구를 동시에 현재 페이지로 강조하지 않는다.
- 미저장 입력이 있는 상태의 대상 변경은 저장·변경 취소 절차로 보호한다. 업무 관점 변경이 재무 수치나 검토 기록을 초기화해서는 안 된다.

### B. 중앙: 업무 내용과 시각화

- 중앙의 `범위–자료 요청–대사–…` 단계 이동은 제거한다. 질문 작업 공간의 별도 단계 진행 표시도 중복 이동 수단으로 사용하지 않는다.
- 8단계 업무 선택은 왼쪽 메뉴로 통일한다. 쟁점에서 관련 조서로 이동하는 문맥 링크는 업무 연결 기능이므로 유지한다.
- 공통 제목 영역과 도구줄의 높이를 고정한다. 긴 제목은 최대 두 줄 범위에서 표시하고 전체 제목을 접근 가능한 설명으로 제공한다.
- 재무 실사 분석 안의 `과거 실적 / QoE / 운전자본 / 순차입금 / 현금흐름·CAPEX / 전망`은 업무 내부 분석 탭이므로 유지한다.
- 모든 페이지가 같은 높이의 하위 도구줄을 사용한다. 재무 분석에서는 분석 탭을, 다른 페이지에서는 해당 페이지의 필터·검색·작업 안내를 배치해 본문 시작점을 맞춘다.
- 로딩·오류·빈 데이터 메시지는 중앙 내용 영역 안에서 표시하고 패널이나 공통 제목 영역을 교체하지 않는다.

### C. 오른쪽 위: 항상 열려 있는 상세 영역

- `원문 패널 접기/열기` 버튼, 관련 콜백, 접힘 상태, 2열 전환 스타일을 제거한다. 단순히 버튼만 숨기지 않는다.
- 영역 제목은 `조서·근거 상세`로 통일하고, 내부에 화면에 필요한 검토·편집·원문 내용을 표시한다.
- 항목이 선택되지 않았어도 영역을 유지하고 선택 안내를 보여 준다. 자료가 없거나 원문을 불러오지 못해도 영역 크기를 줄이지 않는다.
- 질문 화면은 상세 영역 안에서 `설정 / 편집 / 원문`을 전환한다. 내부 탭 전환이 아래 자료 목록의 위치·높이에 영향을 주지 않는다.
- 본문·원문 인용 16px, 줄 높이 약 1.7, 보조 메타데이터 최소 14px, 제목 20px를 공통 기준으로 한다.
- 상세 내부만 스크롤한다. 긴 파일명·해시·인용문은 줄바꿈하며 패널 폭을 넓히지 않는다.

### D. 오른쪽 아래: 상시 프로젝트 자료

- 모든 FDD 및 보조 도구 화면에서 **자료 목록 자체**가 기본 표시된다. 팝업·오버레이·접기 전용 버튼은 사용하지 않는다.
- `프로젝트 자료` 제목, 검색창, 유형 필터, 파일 행은 고정 구성이다. 전체 파일은 목록 내부 스크롤로 접근한다. 검색·선택 상태는 같은 투자 대상 내 페이지 이동 시 유지한다.
- `원문 문서`와 `재무 원천표`를 구분해 현재 연결된 자료를 표시한다. 현재 합성 사례에서는 Word 문서 4개와 별도 FDD 재무팩을 같은 출처로 오인하지 않게 한다.
- 각 파일 행: **파일 형식 아이콘 + 파일명 + 수령/추출 상태 + 버전**. 선택한 자료와 현재 조서에 연결된 자료는 서로 다른 표시를 쓴다.
- 파일 클릭 시 오른쪽 위에서 내용을 확인하고 원문 다운로드를 제공한다. 중앙의 분석 페이지는 유지한다. PDF 페이지·표 셀 등 원천 위치가 있으면 함께 이동한다.
- 직접 입력한 CSV는 CSV 아이콘과 입력 원천 표시를 사용한다. Excel에서 열 수 있다는 이유로 `.csv`를 Excel 문서로 표시하지 않는다.
- 프로젝트를 바꾸면 이전 회사의 검색 결과·선택 원문·미리보기를 즉시 분리한다. 연결되지 않은 파일을 업로드 완료로 표시하지 않는다.

### E. 실제 파일 형식 아이콘

| 형식 | 사용할 자산 | 표현 |
|---|---|---|
| `.doc`, `.docx` | Microsoft Word 공식 문서 아이콘 | Word 아이콘 + 파일명 |
| `.xls`, `.xlsx` | Microsoft Excel 공식 문서 아이콘 | Excel 아이콘 + 파일명 |
| `.ppt`, `.pptx` | Microsoft PowerPoint 공식 문서 아이콘 | PowerPoint 아이콘 + 파일명 |
| `.pdf` | Adobe Acrobat 공식 PDF 파일 아이콘 | PDF 아이콘 + 파일명 |
| `.csv`, 기타 | 형식을 정확히 나타내는 문서 아이콘 | 실제 확장자 명시 |

구현 때 공식 배포 자산과 이용 조건을 확인하고 SVG 또는 PNG를 로컬 assets에 포함한다. 출처·버전·이용 조건은 자산 목록에 기록한다. 색상 사각형에 `DOCX` 등을 쓴 현재 배지를 실제 아이콘으로 교체하고, 외부 서버 호출 없이 표시한다. 아이콘은 24~28px이며 색상 외에도 파일명·확장자로 형식을 알 수 있게 한다.

## 4. 화면 틀의 치수와 스크롤 규칙

데스크톱 기준 제안값이며 최종 치수는 캡처를 보고 조정한다. 같은 창 크기에서는 페이지나 업무 관점을 바꿔도 값이 바뀌지 않아야 한다.

| 영역 | 제안 규칙 |
|---|---|
| 상단 | 높이 64px, 항상 같은 위치 |
| 왼쪽 | 폭 256px, 설정/도구/업무 이동을 공통 배치 |
| 오른쪽 | `clamp(420px, 28vw, 520px)` |
| 중앙 | 남은 폭을 사용, `min-width: 0` |
| 간격 | 공통 16px |
| 오른쪽 분할 | 상세 약 60%, 자료 약 40%; 페이지에 따라 변경하지 않음 |
| 화면 높이 | 뷰포트 높이에서 상단과 공통 여백을 뺀 높이 |
| 스크롤 | 중앙 본문·상세 본문·파일 목록·필요 시 왼쪽 메뉴 각각 내부 스크롤 |

`100dvh` 기반 공통 Grid와 `minmax(0, 1fr)`/`min-height: 0`을 사용해 문서 전체가 길어지면서 틀이 움직이는 현상을 막는다. 표가 넓으면 표 내부에서 가로 스크롤하며 페이지 전체에 가로 스크롤을 만들지 않는다. 스크롤바 유무로 열 너비가 바뀌지 않게 한다.

1440px 이상은 세 영역을 상시 표시한다. 1280px에서는 왼쪽 232px·오른쪽 380px 등 별도 고정 규격을 적용하고 중앙 표는 내부 스크롤로 읽는다. 1024px 이하와 200% 확대에서는 작은 화면용 동일 구조를 사용하되 읽기 가능한 최소 폭이 우선이다. 오른쪽 상세·자료는 중앙 아래의 상시 영역으로 재배치하고 페이지별로 임의 숨김 처리하지 않는다. 이 경우 모든 영역을 한 화면 안에 동시에 담는 것은 목표로 삼지 않는다.

## 5. 구현 순서와 변경 대상

1. **공통 틀 구성** — `layout.py`에서 상단·왼쪽 설정/도구·중앙·오른쪽 상세/자료를 항상 생성한다. 페이지 전환 때는 내용 슬롯만 갱신한다.
2. **설정 이동과 중복 메뉴 제거** — `fdd_workspace.py`의 업무 관점/기간을 이동하고 중앙 단계 내비게이션을 제거한다. 질문 화면의 중복 단계 표현도 정리한다.
3. **자료 영역 통합** — `studio.py`, `studio_callbacks.py`, `fdd_callbacks.py`에서 원문 목록·재무 원천 목록과 선택 이벤트를 공통 자료 영역으로 연결한다. 페이지 전환이 자료 목록을 다시 비우지 않게 한다.
4. **항상 열린 상세 영역** — `callbacks.py`의 패널 접기 로직과 관련 테스트·스타일을 제거한다. 기존 원문·편집 동작을 공통 슬롯에 연결한다.
5. **스타일 정리** — 새 파일을 계속 덧붙여 우선순위로 덮어쓰지 않는다. 공통 치수·글꼴·스크롤 규칙을 한 스타일 파일로 모으고 기존 페이지별 프레임 규칙을 제거한다.
6. **아이콘 적용** — 공식 파일 형식 자산을 추가하고 자료 목록·원천 카드·다운로드 주변의 파일 표현을 통일한다.
7. **아래 전체 점검을 수행** — 발견한 잘림·높이 변화·스크롤 이동을 수정한 뒤 캡처와 측정 결과를 함께 남긴다.

계산·공식 점수·원문 저장 값·출처 무결성·승인 경계는 유지한다. 새 저장 서버나 사용자 권한 기능을 구현한 것으로 표시하지 않는다.

## 6. 화면별 점검표

|---|---|
| 1. Deal 개요·실사 범위 | PE/IB/Big 4 전환, 투자 대상/기간 변경, 범위 입력 시 공통 틀 유지 |
| 2. 자료실·자료 요청 | 요청 목록·CSV 입력·긴 파일 목록과 상시 자료 영역의 역할 구분 |
| 3. 재무 데이터·대사 | 긴 대사 표의 내부 가로 스크롤, 원천 선택 및 상세 영역 유지 |
| 4. 재무 실사 분석 | 6개 분석 탭 모두 동일 본문 시작점, 워터폴·그래프의 잘림 없음 |
| 5. 쟁점·경영진 Q&A | 긴 답변·입력창이 상세 또는 자료 영역의 경계를 밀지 않음 |
| 6. 조정사항·거래 영향 | 조정 선택·원천 확인·EV 입력·결과 갱신 때 틀 유지 |
| 7. 작성·검토 관리 | 의견 작성·제출·검토 확정 상태 전환 때 틀 유지 |
| 8. 보고서·산출물 | 다운로드·제한사항 표시 중 자료 목록과 상세 유지 |
| 질문 검토 작업 공간 | 설정/편집/원문 전환, 초안 저장·선택 상태 유지 |
| 원문·증빙 탐색 | 검색·파일 클릭·원문 이동, 오른쪽 아래 자료 목록 유지 |
| 투자 가설 | 긴 주장·인용문 확인, 같은 제목/본문 위치 유지 |
| 질문 중요도 평가 | 표 정렬·원천 확인·점수 워터폴 확인 |
| 새 증거 반영 | 승인/반려 후 상태와 원문 무결성 유지 |
| 증빙 요청 분석 | Bayesian/EIG 그래프가 패널 밖으로 넘치지 않음 |
| 예비 심사 문서 | 승인·다운로드 상태가 프레임에 영향을 주지 않음 |
| 기존 증빙 개요 | 개요 내부 카드가 공통 제목과 중복되지 않음 |
| 기존 수동 FDD 조서 | 입력창과 다운로드가 새 공통 틀 안에서 동작 |

## 7. 완료 기준

- 17개 화면을 하나씩 열어 캡처를 확인한다. FDD 8개는 3개 업무 관점 모두 확인하고 재무 분석 6개 하위 탭도 확인한다.
- 1440×900, 1920×1080, 2560×1440 및 1280×800에서 같은 해상도 내 패널 x/y/폭/높이 차이가 1px 이내다. 중앙 본문 시작점도 페이지 간 1px 이내로 일치한다.
- 화면 이동·중앙 스크롤·상세 스크롤·자료 스크롤 전후에 공통 영역의 경계가 움직이지 않는다. 문서 전체 스크롤로 다른 패널이 따라 움직이지 않는다.
- 모든 화면에서 클릭 없이 자료 목록이 보인다. 목록 검색·선택·원문 확인이 작동하고 회사 간 자료가 섞이지 않는다.
- 파일 수가 많음, 파일 없음, 긴 한글명, 긴 인용문, 로딩, 오류, 데이터 미제공, 미저장 초안 상태를 각각 확인한다.
- 키보드로 왼쪽 메뉴·검색·파일 선택·본문·상세에 접근할 수 있다. 초점 표시가 유지되고 숨은 접기 버튼이 탭 순서에 남지 않는다.
- 1024px 이하와 200% 확대에서는 정해진 작은 화면용 배치로 전환되며 화면마다 다른 배치를 사용하지 않는다. 본문 글자를 줄여 세 열을 억지로 유지하지 않는다.
- 기존 계산·증빙 승인·자료 다운로드·Excel/보고서 내보내기 검사를 유지한다. 패널 접기 검사는 제거하고 항상 표시·고정 경계·자료 유지 검사로 교체한다.
- 최종 보고는 화면별 점검 결과, 수정 전후 캡처, 측정값 및 남은 제약을 함께 제공한다.
